# Процесс изменений

1. Любое изменение требования делается в ветке и через PR в репо требований. Прямой push в main запрещён.
2. CI: `validate.py` + `generate.py --check` обязательны, трассировка рекомендательная (advisory).
3. Мерж возможен только после одобрения человеком-владельцем области (CODEOWNERS на `requirements/<scope>/`).
4. PR реализации ссылается на PR требования и ADR.

## Пример: агент предлагает требование из разбора коммитов
Ежедневно (routine/cron) агент читает новые коммиты продукта и ищет: новые сущности с ПДн, захардкоженные значения, опасные миграции, отступления от ADR.

Результатом будет заметка с разбором и PR такого вида:

```
Title: req: X-SEC-005: классификация ПДн в таблице customer_contacts (draft)

Источник: коммиты a1b2c3d..e4f5a6b (миграция V12 добавила full_name, phone без срока хранения).
Предлагаю:
- новое требование X-SEC-005 (status: draft, hypothesis: true);
- доказательство к X-SEC-003: links.docs += заметка разбора.
Вопросы владельцу: нужен ли телефон в аудите? Какой срок хранения?
Требует одобрения человеком. Статус не повышен.
```
Файл требования содержит в `source` хэши коммитов, а в «Обосновании» описано, что именно найдено. Человек правит, одобряет или закрывает PR.
