# Промпт: перенести требования из разбора продукта в каталог

```
Ты переносишь требования из разбора продукта <продукт и версия> в каталог типовых требований.
Источник: <путь к очищенному разбору>. Читай docs/catalog.md и reqs.config.yaml.

1. Для каждого пункта найди домен и код возможности naming-standard. Если кода нет, не придумывай: запиши пункт в backlog профиля и вопрос владельцу.
2. Проверь, нет ли уже такого требования в catalog/. Если есть, добавь источник в source, а не новое требование.
3. Формулировка: одно поведение, «Система должна …», без названий продуктов. Пороги вынеси в params. Названия продуктов только в realizations (карточки tech-radar).
4. MoSCoW из разбора переводи в level: M -> MUST, S -> SHOULD, C -> MAY, W не переносится.
5. Колонки «как в продукте» и статусы перенеси в assessments/<product>-<version>.md, а не в требование.
6. Номер: следующий свободный по catalog/ids.lock. Статус draft или proposed, выше не повышай.
7. make register && make check. Покажи список новых ID, пропущенных пунктов и вопросов.
```
