# AGENTS.md: инструкции для ИИ-агентов

Это репо требований проекта. Правила для Cursor лежат в `.cursor/rules/*.mdc`; ниже то же для любых агентов.

1. Читай `reqs.config.yaml`: это источник префиксов, типов, областей и статусов.
2. Новое требование: копия `templates/requirement.md` в `requirements/<scope>/<ID>.md`, status `draft`.
3. Связь с решениями: `links.adr` в требовании + `Связанные требования:` в ADR.
4. Перед коммитом: `make check` (validate + актуальность реестра). Красный CI не обходить.
5. Изменения вносятся только через PR; статусы approved/verified ставит человек.
6. Предложения из разбора коммитов: отдельный PR, в `source` указаны хэши коммитов, `hypothesis: true`, если вывод не подтверждён.
7. Не придумывай ID без проверки свободного номера; не удаляй требования, а переводи их в `deprecated`.
8. Нельзя: секреты, ПДн, ФИО, внутренние хосты/IP, данные клиентов.
9. Типовые требования: `catalog/<domain>/T-<DOM>-NNN.md` по `templates/typical-requirement.md`. Без названий продуктов в разделах «Требование» и «Критерии приёмки», продукты только в `realizations`. Номер по `catalog/ids.lock`. Порядок: `docs/catalog.md`.
10. Приоритет требования проекта по MoSCoW: `M`, `S`, `C`, `W`. В каталоге приоритета нет, там `level`: MUST, SHOULD, MAY.
11. Принятие типовых требований проектом: `adoption.yaml` (`docs/adoption.md`). Файлы `requirements/_catalog/` генерирует `scripts/generate.py`, руками их не правят.

Готовые промпты: `docs/prompts/`.
